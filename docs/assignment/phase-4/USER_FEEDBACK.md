# Direct feedback from the product owner (top priority, overrides reviewer nitpicks)

New items are appended at the bottom. Every fixer must check the items in its area; every reviewer must deduct for any item still not solved.

1. Trip page (/trips/<id>, e.g. 22:49 B with ?od=Ada Exchange) is "really hard to orient in". Observed problems:
   - Title says "22:49 Campus Gate → Hopper Hall" but the user boards at Ada Exchange at 23:06; the header, subtitle ("Jízda 4 min · 7 zastávek") and status card mix the whole trip with the user's segment. Make it obvious: which trip this is, where I board, where I get off, when, and how long MY ride is.
   - The stop list hides 5 earlier stops behind "Zobrazit 5 předchozích zastávek", so the route looks like 2 stops; show the full route with the user's segment highlighted and the rest dimmed (like IDOS / DB trip detail).
   - "Dál z konečné Hopper Hall / Další spoj této trasy 07:00 zítra" is confusing and not useful; replace with something a passenger actually needs (onward connections from the destination, or remove).
   - Labels "přij./odj.", "tady nastupujete", "KONEČNÁ · PŘÍJEZD" are cramped and inconsistent; one clear time column, clear boarding/alighting markers.
   - Overall: one clear reading order top-to-bottom, model it on IDOS spoj detail and DB Navigator journey detail.

2. Orient the user with visual PATTERNS, not text. Labels and explanations are a last resort; the user reads shape, colour, icon and position far faster than words.
   - Each kind of thing must have its own instantly recognisable visual signature, used identically everywhere: a LINE (coloured line badge + route strip), a STOP (stop sign/pin shape + photo), a TRIP (vertical route spine with times), a CONNECTION from the planner (journey bar with legs coloured by line, like IDOS/Citymapper), a DEPARTURE BOARD (dark split-flap board). Never reuse one pattern for another kind.
   - Today too many pages look like the same generic table/list, so the user can't tell where he is. Pages must look different from each other because their content type differs, while sharing the same tokens/type/spacing.
   - Replace explanatory text, legends and hint lines with self-evident visuals (icons, position on a route line, colour, emphasis, timeline position). Keep text short.
   - Consistency rule: the SAME kind of information always uses the SAME component and look on every page (e.g. a line badge, a time, a stop name link, "boarding here" marker).

3. Remove generic "AI look" decoration. Specifically: thick coloured accent bars on one side/top of cards (border-top / border-left stripes, e.g. on "STAV SPOJE", the departure board, line cards, "Linky na zastávce", stop rows), and similar clichés (eyebrow label + short coloured underline next to every section heading, glowing pills, gradient blobs). Audit every page and drop or replace them; use line colour only where it carries meaning (the line badge, the route line itself). Cards should be separated by spacing, surface tone and typography instead.

4. Cut small grey helper text. Small muted lines like "Jízda 4 min · 7 zastávek", "ze zastávky X · živě podle pražského času", "Spoje, které tu končí, nejsou uvedeny…", hint lines under inputs, "jede denně", footnotes — users skip them and they add noise. For each one: delete it if it is not essential; if the information matters, show it as a real visual element (a duration chip on the route, a stop count shown by the route itself, an icon state) at readable size. Target: no paragraph-sized or single-line muted helper text on any page except true error/empty states.

5. Stop page: replace the two buttons "Spojení odtud" / "Spojení sem" with ONE primary "Trasa" button like Google Maps "Directions": it opens the planner (/spojeni) with this stop prefilled as the destination ("sem") and the origin field focused (user can swap with the planner's swap button). Use a route/directions icon. Apply the same single "Trasa" entry point anywhere else the two buttons appear.

6. Stop departure board, "Celý den" view: the full-width green "TEĎ · 19:29" bar cutting through the list is confusing. Replace the flat list with a real vertical TIMELINE: a time axis on the left (hours), departures placed along it, past ones faded, and a thin "now" marker on the axis (not a full-width banner), so the gap between departures is visible (e.g. nothing 07:16–20:04 reads as a long empty stretch). Also: the "ZA" column is empty in this view and "přes …", "stojí 1 min", "příjezd" small texts add noise (see item 4) – show dwell/arrival only when it matters, visually.

7. Departure rows: "přes Compiler Court" shows only one intermediate stop, which is misleading. If "přes" is shown, show ALL the remaining stops of that trip after this stop (compact, like PID/IDOS boards: small stop sequence or a mini route strip with stop names, wrapping/truncating gracefully with the full list on hover/expand), with the user's chosen destination ("Kam jedete") highlighted. Otherwise drop "přes" entirely.

8. ONE corner radius everywhere. Today there are ~4 (pill inputs/toggles, large card radius, small badge radius, row radius). Pick a single radius token and use it for every card, row, input, button, toggle, chip and badge (line badges included); remove pill/fully-rounded shapes and per-component radii. Enforce via one CSS token; grep for border-radius / rounded-* / --radius-* and remove the others. (Circles only where something is literally a dot on a route line.)

9. LIGHT MODE is broken: in light theme the stop page's departure board (and other always-dark panels: trip status card, timetable cards, etc.) stay a big black slab on a cream page, and the "Spojení" buttons/inputs don't match. Every component must have proper light AND dark variants from the shared tokens (no hard-coded dark board colours); the board may keep its "signage" identity but must sit naturally in the light page. Screenshot every page in BOTH themes: the screenshot helper takes a 4th argument, e.g. `node scripts/shot.mjs <url> <out.png> 1280 light` (default dark). Reviewers deduct for any page that looks wrong in either theme.
